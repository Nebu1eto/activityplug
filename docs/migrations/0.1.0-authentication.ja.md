0.1.0 の認証移行
================

ActivityPlug 0.1.0 の公開 API は、HTTP の `Authorization` ヘッダーから
のみセッションを受け取ります。この変更により、セッション識別子が URL、
リクエスト本文、ブラウザー履歴、ログ、リファラーから漏えいすることを
防ぎます。


削除された入力
--------------

アカウントの投稿、フォロワー、フォロー中の取得、投稿および投稿履歴の
取得、公開およびローカルタイムライン、検索、投票の取得、ホーム
タイムラインおよび通知の WebSocket URL から `sessionId` クエリー
パラメーターを削除しました。すべての `/api/v1/**` URL で `sessionId`
クエリーパラメーターが拒否されます。

すべての HTTP JSON およびマルチパートリクエスト本文から、トップレベルの
`sessionId` フィールドを削除しました。このフィールドを含む本文は、無視
されず拒否されます。

GraphQL の `accountFollowers`、`accountFollowing`、`accountPosts`、
`accountRelationship`、`filter`、`filters`、`followRequests`、
`homeTimeline`、`list`、`listAccounts`、`listTimeline`、`lists`、
`notificationUnreadCount`、`notifications`、`poll`、`postHistory`、
`publicTimeline`、`scheduledPost`、`scheduledPosts`、`viewer`、
`acceptFollowRequest`、`authRefresh`、`authRevoke`、`blockAccount`、
`bookmarkPost`、`clearNotifications`、`deleteFilter`、`deleteList`、
`deletePost`、`deleteScheduledPost`、`dismissNotification`、
`favouritePost`、`followAccount`、`rejectFollowRequest`、`unblockAccount`、
`unbookmarkPost`、`unboostPost`、`unfavouritePost`、`unfollowAccount`、
`unmuteAccount` から `sessionId` 引数を削除しました。
`notificationStream` と `timelineStream` からも削除しました。

GraphQL 入力オブジェクトの `BoostPostInput`、`CreateFilterInput`、
`CreateListInput`、`CreatePostInput`、`DeleteMediaInput`、
`ListAccountInput`、`MuteAccountInput`、`ReactPostInput`、
`SchedulePostInput`、`SearchInput`、`UpdateFilterInput`、`UpdateListInput`、
`UpdateMediaInput`、`UpdatePostInput`、`UpdateProfileInput`、
`UpdateScheduledPostInput`、`UploadMediaFromUrlInput`、`UploadMediaInput`、
`VotePollInput` にも `sessionId` はありません。


0.1.0 より前
------------

~~~~ http
GET /api/v1/timelines/home?sessionId=$ACTIVITYPLUG_SESSION HTTP/1.1
Host: proxy.example
~~~~


0.1.0 の代替
------------

~~~~ http
GET /api/v1/timelines/home HTTP/1.1
Host: proxy.example
Authorization: Bearer $ACTIVITYPLUG_SESSION
~~~~

GraphQL HTTP リクエストも同じ Bearer ヘッダーを使用し、引数と入力
オブジェクトから `sessionId` を省略します。WebSocket アップグレードも
Bearer ヘッダーを使用し、WebSocket URL の認証情報は拒否されます。

ブラウザーアプリケーションは `/v1/browser/**` と不透明な BFF Cookie を
使用する必要があります。ActivityPlug セッション ID を読み取ったり保存
したりしてはいけません。URL は履歴、ログ、リファラーから漏えいするため、
クエリー認証情報の互換エイリアスは提供しません。
