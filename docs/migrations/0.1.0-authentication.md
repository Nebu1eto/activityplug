Authentication migration for 0.1.0
==================================

ActivityPlug 0.1.0 accepts public API sessions only through the HTTP
`Authorization` header. This change prevents session identifiers from leaking
through URLs, request bodies, browser history, logs, and referrers.


Removed inputs
--------------

The `sessionId` query parameter was removed from account post, follower, and
following reads; post and post-history reads; public and local timelines;
search; poll reads; and home-timeline and notification WebSocket URLs. A
`sessionId` query parameter on any `/api/v1/**` URL is now rejected.

The top-level `sessionId` field was removed from every HTTP JSON and multipart
request body. A body containing that field is now rejected rather than ignored.

GraphQL removed the `sessionId` argument from `accountFollowers`,
`accountFollowing`, `accountPosts`, `accountRelationship`, `filter`, `filters`,
`followRequests`, `homeTimeline`, `list`, `listAccounts`, `listTimeline`,
`lists`, `notificationUnreadCount`, `notifications`, `poll`, `postHistory`,
`publicTimeline`, `scheduledPost`, `scheduledPosts`, `viewer`,
`acceptFollowRequest`, `authRefresh`, `authRevoke`, `blockAccount`,
`bookmarkPost`, `clearNotifications`, `deleteFilter`, `deleteList`,
`deletePost`, `deleteScheduledPost`, `dismissNotification`, `favouritePost`,
`followAccount`, `rejectFollowRequest`, `unblockAccount`, `unbookmarkPost`,
`unboostPost`, `unfavouritePost`, `unfollowAccount`, and `unmuteAccount`.
It was also removed from `notificationStream` and `timelineStream`.

GraphQL input objects no longer contain `sessionId` in `BoostPostInput`,
`CreateFilterInput`, `CreateListInput`, `CreatePostInput`, `DeleteMediaInput`,
`ListAccountInput`, `MuteAccountInput`, `ReactPostInput`, `SchedulePostInput`,
`SearchInput`, `UpdateFilterInput`, `UpdateListInput`, `UpdateMediaInput`,
`UpdatePostInput`, `UpdateProfileInput`, `UpdateScheduledPostInput`,
`UploadMediaFromUrlInput`, `UploadMediaInput`, or `VotePollInput`.


Before 0.1.0
------------

~~~~ http
GET /api/v1/timelines/home?sessionId=$ACTIVITYPLUG_SESSION HTTP/1.1
Host: proxy.example
~~~~


0.1.0 replacement
-----------------

~~~~ http
GET /api/v1/timelines/home HTTP/1.1
Host: proxy.example
Authorization: Bearer $ACTIVITYPLUG_SESSION
~~~~

GraphQL HTTP requests use the same Bearer header and omit `sessionId` from
arguments and input objects. WebSocket upgrades also use the Bearer header;
credentials in WebSocket URLs are rejected.

Browser applications must use `/v1/browser/**` and its opaque BFF cookie. They
must not read or store an ActivityPlug session ID. There is no query-credential
compatibility alias because URLs can leak through history, logs, and referrers.
